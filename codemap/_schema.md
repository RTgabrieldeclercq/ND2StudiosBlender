# codemap record schema

Six files under `codemap/gen/`, **one fact per line**, so one `grep` returns one complete
record and nothing else. Keys are short because every character is paid on every lookup;
they are defined once here and then used bare everywhere.

Generated by `scripts/_codemap.py write` (source: [nodegraph/codemap.py](../nodegraph/codemap.py)).
Never hand-edit — the first line of each file says so, and `nodegraph.selftest.test_codemap`
will notice.

## How to read this page

You almost certainly do not need to. Grep the file, read the record: the field names are
close enough to English that `"gran":{"2D":"TILEABLE","3D":"WHOLE_VOLUME"}` explains itself.
Come here when a key is opaque.

---

## `nodes.jsonl` — one per registered op, keyed `op`

```
grep '"op":"enhance.gaussian"' codemap/gen/nodes.jsonl
```

| key | meaning |
|---|---|
| `op` | the op_key — the node's stable identity everywhere in this repo |
| `label` `cat` `desc` | palette name, category, one-line description |
| `mod` `owner` | the file that defines it, and its dotted module name |
| `compute` | the compute function's name (find it with `grep '"id":".*<name>"' symbols.jsonl`) |
| `gran` | data-access footprint: a `Granularity` name, or one per mode value |
| `kax` | kernel axes — which axes the maths reaches across |
| `fp_mode` | which Mode keys `gran`/`kax` (usually `dim`, the 2D/3D lever) |
| `in` `out` | socket names; the contracts are in `sockets.jsonl` |
| `modes` | in-body dropdowns: `n` name, `choices`, `default`, `role` (`dim_lever` = the header switch) |
| `reads` `adds` | domains required upstream / produced. Absent = none |
| `reads_by_mode` | the conditional half: `{mode: {value: [domain…]}}` — a per-branch rail |
| `d2` `d3` | supports 2D / true 3D. **Always present**, so absence never has to be interpreted |
| `meta` | name of the `meta_transform` — this node changes axes or calibration |
| `extra_layers` | name of the resolver declaring layers that have no output socket |
| `trained` | a loaded model checkpoint fills some of this node's sockets |
| `kernel_doc` | path to the kernel's integration contract — usually the best next read |
| `params_read` | param keys the compute actually reads, resolved through shared helpers |
| `cdoc` | the compute's docstring, whitespace-collapsed. The richest prose about the node |
| `gui_only` | registered by `nodelab_v2`, not the catalog: not hot-reloadable, invisible to the catalog-wide gates |
| `fp` | closure fingerprint (volatile — see below) |

## `sockets.jsonl` — one per socket and per mode, keyed `key`

`key` is `<op>:<in|out|mode>:<name>`.

```
grep '"key":"enhance.gaussian:in:sigma"' codemap/gen/sockets.jsonl
```

Fields are `SocketSpec`/`ModeSpec` fields verbatim, **with defaults elided** — an absent key
means "declared default". The ones worth knowing: `unit` (the physical unit a value is
given in), `derive` (an expression computing the default from the image's own calibration),
`available_in` (mode gating — the socket only exists in these mode values), `layer_in`/
`layer_out` (this socket names an attribute layer rather than carrying data), `kernel_param`
(changing it changes the spatial footprint), `presentation` (excluded from the memo hash),
`choices`/`choice_docs` (closed dropdown and per-option prose), `description` (the hover
prose — gate-enforced to be real prose, not a restatement of the name).

Reflective over `dataclasses.fields`, so a field added to `SocketSpec` appears here without
anyone editing this page.

## `modules.jsonl` — one per `.py` file, keyed `mod`

```
grep '"path":"nodegraph/streaming.py"' codemap/gen/modules.jsonl
```

`role` is the first line of the module docstring. `cls`/`fn` are top-level names. `imp` is
this module's first-party dependencies; `imp_by_n` is how many modules import it — the list
itself is in `imports.jsonl`, because a hub like `nodegraph.registry` has ~100 importers and
inlining them would make its card cost more than the file it describes.

## `symbols.jsonl` — one per top-level def/class and per method, keyed `id`

```
grep '"id":"nodegraph.registry.NodeSpec.resolve_granularity"' codemap/gen/symbols.jsonl
grep '"id":".*resolve_granularity"' codemap/gen/symbols.jsonl      # when you only know the name
```

`sig` is the signature as source text; `doc` is the first line of the docstring; `file` +
`line` locate it. A name defined twice in one module gets `#2` appended to the second id
(this happens — see `nodegraph.kernels.registration.apply_frame`), so a plain grep still
finds both.

**Coverage boundary:** `scripts/` is indexed at module granularity only. Its helpers are
nobody's API and several of those files are live experiments whose functions come and go.
Their names are still in the module card's `fn` list.

## `imports.jsonl` — one per first-party edge

```
grep '"dst":"nodegraph.memo"' codemap/gen/imports.jsonl     # who depends on the memo
grep '"src":"nodelab_v2.runner"' codemap/gen/imports.jsonl  # what the runner needs
```

`lazy: true` means every import of that module is inside a function body — the pattern every
math kernel uses so the engine stays importable without tensorflow/numba/torch. A hard
dependency and an optional backend look completely different in this file, which is the
point of it existing alongside `modules.jsonl`.

## `vocab.jsonl` — the controlled vocabulary, keyed `t` within `group`

```
grep '"t":"WHOLE_VOLUME"' codemap/gen/vocab.jsonl
```

Groups: `Domain` (the eleven attribute domains, with their prose), `Granularity` (the five
footprints), `SocketType`, `meta_transform` (the named envelope transforms). Harvested from
the enums, because a hand-written glossary is the first thing to rot.

## `MANIFEST.json`

Counts, per-root LOC, and a fingerprint per file plus one over all of them. `fp_all` is the
one-grep answer to "is the map I am looking at the one this code produces?".

## Volatile fields

`symbols.line`, `modules.loc` and `nodes.fp` move whenever code moves, not when a contract
changes. `scripts/_codemap.py write` refreshes them like everything else, but the **gate
ignores them**: a gate that fires because someone added a blank line to `engine.py` is a gate
people learn to bypass, and then it is not protecting anything. `_codemap.py check` still
reports the count so you know the map wants regenerating.

The practical consequence for a reader: a `line` may be a few lines off after someone else's
edit. Grep the symbol name rather than trusting the offset blindly.
