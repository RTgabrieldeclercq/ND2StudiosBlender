# V4.10 — Scene viewer: composable 3-D HTML viewers from the node graph

*Design record, 2026-10-08. Branch `flow-viewer-export`. Status: implemented in the first
cut described in §6; the later cuts in §7 are not.*

## 1. The ask

The lab's data is volumetric and dynamic, and one experiment is several acquisitions of the
same place: a bead-laden gel volume whose deformation a DVC gives, a cell channel on top of
it whose cells are segmented, measured (area, position, density) and tracked or run through
PIV for velocities, and reporter beads (ELISA-on-bead) whose intensity is read out against
time or condition. The request: build such a composite from the graph — merge the volumes
of one experiment, overlay each analysis on its volume — and write it out as one
self-contained HTML viewer, the way `io.write_flow_viewer` already does for one PIV field.

## 2. Why not more exporters

`io.write_flow_viewer` is one page for one kind of data: a fixed set of geometry builders
wired to a fixed UI. A second such node per data kind (one for DVC, one for cells, one for
tracks …) cannot show two of them in one frame, which is the whole point. The viewer has to
be a *scene* — a list of layers in a shared frame — and the graph has to be able to say
which layer comes from which Dataset.

## 3. The model: layer specs ride the wire, geometry is built once at the sink

```
load A ─ DVC ─ Scene: Volume ─ Scene: Vectors ─────────┐
load B ─ segment ─ measure ─ track ─ Scene: Objects ─ Scene: Tracks ─┤── Export Scene Viewer
load C ─ detect beads ─ measure ─ Scene: Series ───────┘
```

* A **layer node** (`scene.*`) is a tap. It appends one *layer spec* — a small JSON-able
  dict: the kind, which layer/columns/channel to read, and the style — to the stream's
  metadata under `scene_layers`, and hands the Dataset through untouched. It builds no
  geometry. The same function writes the spec at edit time (`meta_transform`) and in the
  compute (`with_metadata`), so the envelope and the payload cannot drift
  (`wire-node-v2` §7). Several layer nodes chained on one stream accumulate.
* **`scene.place`** is the same kind of tap for the stream's *frame*: offsets in µm, the
  Stitch handedness flags, and whether positions are laid out by the stage log or stacked
  at the origin. Without it the exporter places positions by `stage_xy_um` exactly as
  Stitch and the flow viewer do.
* **`io.write_scene_viewer`** is the only sink. It takes up to eight Datasets through a
  grow group (one empty slot at a time, like Timeseries Builder), reads every input's
  `scene_layers` and `scene_frame`, converts each layer to world geometry in **µm** with
  that input's own calibration, writes one page, and returns the first input unchanged
  plus a `scene_viewer_report`. An input with no layer spec and an image gets a default
  volume layer; one with neither is refused by name.

Why metadata and not a new Dataset domain: a spec is a few hundred bytes and must survive
every node between the layer node and the sink without any of them knowing about scenes;
`Dataset.metadata` is the one slot that already flows like that (`__struct_zkind__` is the
precedent). The geometry has no honest home in the Dataset model (a coarse display mesh is
neither a Voxel layer at the image's resolution nor a structure table) and is the sink's
private intermediate, like the flow viewer's velocity grid.

## 4. The world frame

One frame, in µm, right-handed with z up. For a Dataset with `pixel_size_um = px`,
`z_step_um = dz`, position offsets `(oy, ox)` from the stage log (pixels, Stitch's
mapping, the `flip_x` / `flip_y` flags of `scene.place`) and the stream's `scene.place`
offsets `(Ox, Oy, Oz)`:

```
X = Ox + (ox + x) · px          Y = Oy + (oy + y) · px          Z = Oz + z · dz
```

`x, y` are image pixels, `z` the plane index (`z_kind = plane_index`) or the sub-pixel z
(`subpixel`). A multi-plane input without `z_step_um` is refused (the flow viewer's rule:
never a guessed z-stretch). The page stores every buffer in this frame and flips Y for
display so the image's +y (down) and the stage's +y agree with the flow viewer's view.
Time is seconds when the input carries `dt_s`, else the frame index; the page's timeline
is the union of every dynamic layer's frame times and each layer shows its latest frame
at or before the cursor. Static layers are always shown.

## 5. Layer kinds

| kind | node | reads | geometry in the page |
|---|---|---|---|
| volume | `scene.volume` | one image channel, every position, t (dynamic) | a uint8 brick per frame (`voxel_budget` voxels, mean-downsampled, windowed by percentiles) as a WebGL2 3-D texture; drawn as MIP ray-march, three orthogonal slices, or an iso-surface mesh (marching cubes at a percentile level) |
| vectors | `scene.vectors` | a Point table with `vx,vy[,vz]` (µm/s) or `disp_x,disp_y[,disp_z]` (µm) | line glyphs per vector scaled to the window pitch (auto) or a fixed µm per unit, coloured by magnitude / vertical component / uniform; optional streamlines through the gridded field |
| objects | `scene.objects` | a Point or Label table | one sphere per row, radius from `area` (equivalent circle) or a fixed µm, coloured by a column or uniform; a frame per t |
| tracks | `scene.tracks` | a Track table + its member table | one polyline per track, coloured by track / time / speed; the page reveals a track up to the time cursor with a comet tail |
| series | `scene.series` | a column of a Point or Label table | a 2-D chart panel (reducer per timepoint, optionally one line per position) with a cursor tied to the timeline |

`io.write_flow_viewer` stays as it is: the paper's specialised page (continuity-derived
`w`, grains, vessels, bundles) with its own template. A `flow` layer kind that reuses its
kernel inside a scene is §7.

## 6. What the first cut ships

* `nodegraph/kernels/scene_viewer.py` — Qt-free geometry builders, one per kind, a
  `pack()` that serialises the scene, and `render_html()`; `scene_viewer.md` is its
  contract; `scene_viewer_template.html` the page (WebGL2, no dependencies: layer panel,
  timeline, orbit/pan/zoom camera with view presets, µm axes + grid, per-layer legend,
  chart panel, PNG snapshot, `?embed=1`, the saved-view config API of the flow viewer).
* Nodes: `scene.place`, `scene.volume`, `scene.vectors`, `scene.objects`,
  `scene.tracks`, `scene.series`, `io.write_scene_viewer`. Category `scene` (its own
  palette colour), role `scene_composition` (stage `control_and_present`, page
  `analyze`); the sink in `input_output`.
* Shared placement helpers moved to `catalog/_shared/scene.py` (tile offsets from the
  stage log, grid pitch) so the flow viewer and the scene sink use one mapping.
* Selftest `test_scene_viewer`: a synthetic two-input scene (a dynamic volume + DVC-style
  vectors; cells measured, tracked and charted) exported end to end, spec accumulation at
  edit time == payload, every kind's refusal, hashes apart per mode, calibration fenced.
* `graphs/alia_chip_scene.nd2graph.json`: the alia-chip PIV field + granule volume as a
  scene, the first real page.

## 7. Later cuts (not built)

* A `flow` layer kind wrapping `kernels/flow_viewer` (continuity `w`, grains, vessels).
* Label iso-surfaces per object (`scene.objects` draws spheres now).
* Density fields (a kernel-density Voxel layer upstream is the honest route; the volume
  layer then draws it).
* Time alignment by acquisition clock across inputs that do not share `dt_s`.
* A deformed-mesh / strain layer from the DVC strain columns.
