# ND2Studios V5.00 "Figures" — the Analysis page becomes an interactive figure canvas

- **Date:** 2026-11-03, revision 2 (proposal, not yet started). Revision 1 proposed a
  properties-panel editor over a matplotlib render; the user asked for an **interactive
  canvas with extreme editing of plots and overlays alike**, with linked widgets (a zoom
  popout placed by metadata, a twin image carrying a user-normalised speed heat layer over
  an auto-LUT image). This revision is built around that.
- **Author:** Claude (Gabriel's session).
- **Status:** design record. Every path and symbol was checked against `codemap/gen/*` on
  the date above; nothing under `nodegraph/` or `nodelab_v2/` has been changed.

---

## 1. Goal

An **Analysis** page is no longer a node canvas. It is a **figure canvas**: a journal-sized
page on which the user places, drags, links and restyles *items* — images, montages, zoom
popouts, heat layers, vectors, charts, colour bars, histograms, scale bars, text, arrows —
each fed by a named Page Output of the upstream pages and by the metadata those outputs
carry. The page first asks what the user wants to make, then everything is direct
manipulation: drag a source onto the page and it is an image; alt-drag a box on it and a
zoom popout appears, linked; drop a measured column on an image and it becomes a heat
layer; drop a column on a chart axis; twin an image and give the twin a different layer;
share one display range across every panel that must be comparable. Preview and export
are the same painter, so what is on screen is what the PDF holds.

**Non-goals.** No new node types for figures. The `plot.*`, `table.*` and `io.write_*`
nodes stay unchanged for Free pages, LabLink recipes and scripts; a node's picture can be
placed on the page as an item. The Viewer's live overlays stay as they are; the canvas
*reuses* their painter (§4.4) rather than replacing it.

## 2. What a confocal figure contains — and what feeds it today

Community guidance (Jambor et al. 2021, PLOS Biol 19:e3001161, a survey of 580 papers;
Schmied et al. 2023/2024, Nat Methods 21:170, the community checklists) asks for: a scale
bar on every image; insets whose origin box is marked on the parent; colour choices a
colour-blind reader can read (grey for a single channel, magenta/green/cyan merges, no
rainbow for intensity); the display range stated and *shared* across panels that are
compared; annotations and colours explained; what is shown named — channel, Z, T,
position; the acquisition stated in the legend (objective, NA, pixel size, z-step, time
interval); vector output with legible type. Those rules become checks the editor runs on
the page (§4.8).

The table maps each representation scientists use to the data it needs, what the catalog
and the metadata already provide, and the canvas item that draws it. "Gap" marks what
V5.00 adds, always as a Qt-free engine helper that derives from a pulled Dataset (never a
new node) unless stated.

## 3. Decisions to confirm (recommendation first)

1. **Page body, not a new kind.** Kind `analyze`, label "Analysis", gains `"body":
   "figure"`; the canvas dock shows the figure canvas instead of a `CanvasPanel`. The four
   kinds that the roles file, page tabs, Pages panel and LabLink selector key on do not
   change. *(unchanged from rev. 1)*
2. **Nodes stay; the page compiles its sources to a shadow graph.** One hidden `page.input`
   per source (plus the `data.part` / `channel.select` taps inputs already materialise;
   plus `table.concat` / `table.aggregate` / `table.join` / `analysis.if_else` when the
   user pools, aggregates, joins or filters). `Workspace.compose`, the memo, staleness, the
   Node queue and the LabLink publisher work on a figure page unchanged. *(unchanged)*
3. **The canvas is a Qt scene graph; preview and export are one painter.** `FigureScene`
   (`QGraphicsScene`) holds one item per document item, painted with `QPainter`; export
   renders the same scene to `QImage` (raster at dpi), `QSvgGenerator` (SVG, text as
   text) and `QPdfWriter` (PDF, fonts embedded) — all present in the venv. Direct
   manipulation (move, resize, handles, rubber band, snapping, z-order, groups) is native to
   the scene, and the node canvas (`nodelab_v2/scene.py`, `frame_item.py`, `region_box.py`)
   is the in-house precedent. *Replaces rev. 1's matplotlib Agg preview.*
4. **Charts are native scene items, not matplotlib pictures.** The engine computes a
   chart's *geometry* (series polylines, marker positions, bars, violins, ticks and labels,
   legend entries) Qt-free; the GUI paints it. Legend, annotations, axis labels, colour
   bars are sub-items the user drags; axis ranges are dragged on the axis; points are
   picked. Tick placement and formatting use `matplotlib.ticker` and `matplotlib.dates`,
   which are pure Python and need no backend. Matplotlib's Agg remains inside the `plot.*`
   nodes only. *Contingency:* if the native chart painter slips, step 3 ships a chart item
   that paints the node's picture, interactive through the axes transform, under the same
   document schema — the schema and the UI do not change when the painter does.
5. **Figure overlays are painted by the Viewer's own `OverlayRenderer`**, handed a
   plane→page mapping and a stroke scale so sizes are in points rather than screen pixels.
   One implementation of every overlay look, as the two Viewer backends already share.
   The Qt-free overlay maths (`nodelab_v2/overlay_render.py`) moves into the engine as
   `nodegraph/catalog/_shared/overlay_math.py` with a re-export shim (the `tables.py`
   precedent), so headless code and nodes can use it.
6. **Headless render is Qt offscreen in a subprocess.** `python -m nodelab_v2.figure_render
   <file> --page <id> --out <path>` under `QT_QPA_PLATFORM=offscreen` (what the GUI gates
   already run under). The LabLink worker spawns it and stays free of PySide6 itself, which
   is the rule `spreadsheet.py` records.
7. **Legacy Analysis pages that hold nodes** load as Free pages named `<name> (graph)`,
   with a console line; page ids never rebind, so readers keep working. *(unchanged)*
8. **Table synthesis leaves the Analysis primary set**; the page's Data step covers what a
   figure needs. *(unchanged)*
9. **Name.** The panel is the **Figure Editor**; the page kind keeps saying Analysis.

## 4. Design

### 4.1 The page

```
Page(kind="analyze")
  .body = FigureDocument                 # Qt-free, nodelab_v2/figure_document.py
      .figure : dict                     # §4.2, canonical JSON
      .shadow : GraphDocument            # page.input per source (+ taps, + prep nodes)
      .revision                          # figure digest + shadow revision
```

`Workspace` reads `.doc` for graph pages and `.body.shadow` for figure pages wherever it
composes, seeds, summarises or outlines. `page_summary` → *reads* are the sources,
*publishes* is empty; `page_outline` → one row per item. Linked figure pages are refused in
V5.00.

### 4.2 The figure document (schema `nd2studios-figure/1`)

Three collections: **sources** (what is read), **items** (what is on the page) and
**links** (how items depend on one another). Everything is millimetres on the page and
micrometres on the specimen; pixels never appear in the document.

That document *is* the user's example: a montage of the M fields; a popout fed by a
different Page Output whose stage metadata places its box on the right tile of the montage
(`region.from = placement`); the popout under an auto-percentile LUT (or `mode: viewer` to
take the Viewer's window, or `manual`); a twin of it carrying a speed heat layer from the
tracking table with a 0–1 colour bar normalised by a user-chosen maximum speed; a histogram
documenting the display window; an MSD chart whose hover highlights the cell in both
images. Changing the popout's region moves the box on the montage and the twin together;
dragging the box on the montage moves the popout's region; a LUT edit on one twin applies
to both; scrubbing T on the page moves all three images.

**Item kinds.** `image`, `montage`, `picture` (a `plot.*` node's RGB output or an imported
PNG), `chart`, `colorbar`, `histogram`, `scale_bar`, `legend`, `table`, `text`, `arrow`,
`line`, `shape` (rect / ellipse / polygon ROI), `measure_line` (shows its µm length),
`letter`, `ortho`, `kymograph`, `profile`.

**An image item's parts.** `source` + `frame` (`m`, `t`, `z` as an index, `max`, `mean`,
`cursor`), `region` (`full` | `rect_um` | `{"from": "placement"}` — the item's own source
placed inside another item's field by `placement.plan_placement` | `{"object": id}` — the
bounding box of a labelled object, following it over T when tracked | `{"twin": item}`),
`channels[]` (`c`, `rgb`, `mode` = `auto_pct` | `viewer` | `manual` | `shared`, `lo`, `hi`,
`gamma`, `label`), `flip_x` / `flip_y` (the camera handedness the Viewer and `view.overlay`
already apply), `z_mode` / `t_mode` (`plain` | `depth_coded` | `temporal_code`),
`layers[]` (the Viewer's overlay groups — `points`, `labels`, `tracks`, `voxels`,
`vectors`, `field`, `mesh`, `grid` — each with the look fields `overlays.FIELDS` declares,
plus `color_by` where it is new), `decor` (scale bar, time stamp, z-depth, channel labels,
colour bar, border, background).

**Link kinds.** `zoom` (parent draws the child's region as a box with leader lines; either
end edits the other), `twin` (shared region / frame / channels, each override-able;
`flip_x` for a mirrored twin), `lut_share` (one display window across items — the
checklists' "same range across compared panels"), `cursor` (shared M/T/Z across items, the
Compare Viewer's linked cursor), `profile` / `kymograph` (a `line` item feeds a chart),
`highlight` (a chart's hovered row lights the object in image items and in the Viewer),
`colorbar_of` / `legend_of` / `histogram_of` (implicit in `of`).

**Rules carried over from the repo:** canonical JSON (`json_value`), partial dicts merge
on load, every value validated with its spec path named (the `movie_timeline` idiom),
`mode: viewer` is a GUI hint stamped into concrete `lo/hi/gamma` at commit points (the
Movie Editor's LUT stamping) so a saved page renders the same headless.

### 4.3 The engine side (Qt-free, `nodegraph/figure/`)

- `schema.py` — defaults, validation, migration, canonical JSON, digest, link integrity
  (a link to a missing item is refused by name).
- `bind.py` — resolves what each item needs from its source: the plane window to read
  (`placement.field_box`, `plan_placement`, `source_window`, `sub_field_box` — the maths
  `view.overlay` and the Viewer already use), the frame from a cursor, an object's box from
  its table row, a twin's inherited region. Produces a **read plan** per item: `(run_id,
  coords, channels, window, resolution)`.
- `derive.py` — reslice (XZ / YZ), depth-coded and temporal-coded projections, kymograph,
  intensity profile, MSD, coloc statistics; each takes arrays and metadata, returns arrays.
- `series.py` — a chart's data: today's `xy_series`, `distribution_series`,
  `heatmap_grid` (moved here; `_shared/figure.py` delegates so the `plot.*` outputs are
  byte-identical), plus bar, strip / swarm, superplot, rose, survival, hexbin.
- `stats.py` — Welch t, Mann–Whitney, Kruskal–Wallis, one-way ANOVA + Tukey, Pearson /
  Spearman, Manders; bracket geometry.
- `charts.py` — **geometry**: given a chart spec, the resolved series and a text-measure
  callback (the GUI supplies `QFontMetricsF`; the offscreen renderer supplies the same),
  returns axes rectangles in mm, tick positions and labels (`matplotlib.ticker`,
  `matplotlib.dates`), series paths in mm, markers, error bars / bands, bars, box and
  violin polygons, KDE curves, heatmap cells with colours, legend entries, fit lines with
  their equations, stat brackets, colour-bar ramps. Nothing is painted here.
- `layout.py` — page presets (single column 85–89 mm, 1.5 column 114–120 mm, double
  170–183 mm, A4, 16:9), letters, mm grid and snapping, alignment / distribution, style
  sync, the **page checks** (§4.8).
- `legend_text.py` — the auto-generated legend / methods sentence from `acquisition_info`,
  the LUT windows, the scale bars and the sources' lineage.
- `nodegraph/catalog/_shared/overlay_math.py` — `colormap_lut`, `normalize_for_map`,
  `scalar_rgba`, `quiver_arrows` moved down; `nodelab_v2/overlay_render.py` re-exports.

### 4.4 The GUI side (`nodelab_v2/figure_editor/`)

- `scene.py` — `FigureScene` / `FigureView`: page background at true mm scale, zoom and pan,
  rubber-band and click selection, drag / resize handles, snapping to the mm grid and to
  other items' edges, alignment guides, z-order, lock, group; `scene.render` to the three
  export devices at the chosen dpi / vector.
- `items/image.py` — paints the composited window (`viewer.composite_with_clim`, the
  CPU path; the display reads a decimated window, the export re-reads the window at the
  finest pyramid level — `source_window`), flips, coded projections, then calls the
  Viewer's `OverlayRenderer` with an `OverlayFrame` whose `map_pt` is plane→page and
  whose stroke scale makes widths points; decor last. Handles: region box drag inside the
  source, resize, double-click to enter *layer editing* (click a layer to select it, its
  look in Properties).
- `items/montage.py` — a grid of image tiles sharing one LUT; per-tile overrides; labels
  from `position_name` / time / z.
- `items/chart.py` — paints `charts.py` geometry; sub-items for axes, each series, legend,
  annotations, colour bar, brackets; axis-range drag, wheel on an axis, series pick, legend
  drag, text edit in place.
- `items/decor.py` — colour bar, histogram (the Viewer's log-scaled histogram drawn with
  the window marked), scale bar, text, arrow, line, shape, measure line, letter, legend,
  table.
- `links.py` — the link behaviours: zoom box ↔ popout, twins, LUT share, cursor, highlight.
- `sources.py` — the Sources panel: every Page Output of every feeder page, grouped by what
  it carries (from the seed envelopes: image streams by channel, labels, points, tracks,
  fields, meshes, lattice attributes), with M/T/Z/C extents and units; **drag a source onto
  the page** → image item; **drag a column** onto an image → field or colour-by layer,
  onto a chart axis → mapping; the Viewer's *Capture view → page* sends its region, LUT and
  overlay look as a new image item.
- `properties.py` — generated from field specs per item / layer / link kind, pickers from
  the column catalog with units, multi-selection edits shared fields.
- `start_card.py` — *What do you want to make?* cards (Plot, Overlay, Plot + Overlay,
  Table, Montage, Movie hand-off) with readiness lines and **figure templates**.
- `panel.py` — the dock: Sources | canvas | Properties, the toolbar (undo / redo, compute
  sources, cursor strip for linked T/Z/M, style preset, checks, export), undo list
  (commit-on-settle; the document has no undo, as with the Movie Editor).
- `window.py` gains `_FigureHost` beside `_MovieHost`: `figure_state(pid)`,
  `sources(pid)`, `fetch(run_id)`, `finished(run_id)`, `pull_window(run_id, coords,
  channels, window, level)`, `estimate(run_id)`, `commit(pid, text)`, `viewer_lut(run_id)`,
  `viewer_highlight(run_id, m, t, id)`, `show_node(page, node)`, `export(pid, fmt, path)`.
  That list is the panel's whole dependency surface and what the probe drives.
- `figure_render.py` — the offscreen CLI (§3.6), composing through the engine exactly as
  the window does.

### 4.5 Data

1. **Catalog without a pull.** `feeder_pages × outputs_of` and each Output's seed envelope
   (`layer_names`, `column_names`, `axes`, `metadata`) populate the Sources panel and the
   pickers; goal cards light up from the same facts.
2. **Fetch on demand.** Placing a source adds a `page.input` to the shadow graph; the
   editor asks the host for the item's read plan (`bind.py`). A finished result arrives at
   once; an expensive source (DIC / PIV / DVC / SerialTrack, by the governor's estimate)
   shows *Compute (≈ N s)* and is never started unasked; **Auto-compute** covers cheap
   sources. Image items read one window at display resolution; export re-reads at native
   resolution.
3. **Tabulate** with `nodegraph.tables.all_tables`, cached per `(run_id, revision)`.
4. **Prepare** by compiling `table.*` / `analysis.if_else` nodes into the shadow graph; the
   user reads a sentence (*"cells from dish A and dish B, pooled, mean ± sem per condition
   and frame, area > 20 µm²"*).
5. **Stale** items are marked through `on_doc_changed(touched, downstream_of)`; the
   cross-page signature already stales a figure page when an upstream chain changes.

### 4.6 Interaction model — "extreme editing", stated as rules

- Every visible thing is an item or a sub-item with a rect, a z-order and properties; every
  item can be moved, resized, duplicated, twinned, locked, grouped, and restyled in place.
- Any item can host any layer whose source carries that domain; any two items of compatible
  kinds can be linked; a linked property inherits until overridden, and an override is
  visible (a bar on the row, the linked-page idiom).
- A change commits on settle; dragging shows the cheap preview (a scaled pixmap, a moved
  path) and the exact render follows on the worker; latest request wins per item.
- The page has a cursor (M/T/Z) like the Viewer's strips; items joined by a `cursor` link
  follow it, so a figure of a time point is scrubbed, not rebuilt — and a page scrubbed over
  T is the seed of a movie (hand-off to the Movie Editor, later).
- Hover on a chart row with an object id lights that object on every `highlight`-linked
  image and in the Viewer; hover on an image reads the pixel, the object and its row.
- Multi-select edits shared properties at once; **style sync** applies the page preset to
  every item; **page checks** list what the checklists would flag.

### 4.7 Export

PNG / TIFF at the page dpi (and at 2× for review), SVG (text as text), PDF (fonts
embedded), per item or whole page; the **bundle**: the figure file, `<stem>.data/` with one
CSV per chart and per heat layer (the values drawn), `<stem>.figure.json`,
`<stem>.provenance.json` (sources as `<page>:<name>`, file path + size + mtime, each
source's `Engine.lineage`, the LUT windows, the app version, the figure digest) and
`<stem>.legend.txt` — the generated legend sentence. Tables export to CSV / XLSX / text.

### 4.8 Paper-readiness checks (run on the page, shown as a list with jumps)

Scale bar on every image item; an inset has its box on its parent; a single channel is grey
unless the user says otherwise; merges avoid red/green; linked compare panels share a LUT;
every colour bar names its quantity and unit; type ≥ 6 pt at page size; letters present and
in order; a time stamp or z label where the montage axis needs one; the legend text
mentions objective, NA, pixel size, z step and interval when the record has them; export is
vector or ≥ 300 dpi. Every palette passes the dataviz contrast validator.

### 4.9 Headless and LabLink

`nodegraph/figure` and `nodelab_v2/figure_document.py` are Qt-free. Rendering needs Qt
painting, so `nodelab_v2/figure_render.py` runs under the offscreen platform and the LabLink
worker invokes it as a subprocess; the recipe publisher ships the shadow graph with every
page it reads, as an Analysis page is shipped now; the result card's quicklook is the page.

### 4.10 Legacy

Old files: an `analyze` page holding nodes → Free page `<name> (graph)`, console line. The
roles file's `pages.analyze.description` becomes *"Compose figures from the outputs of
refinement and processing pages: images, montages, popouts, heat layers, charts and
tables, exported paper-ready."* MANUAL §2b step 5, §7 Overlays, §11, §15 Plotting notes
are rewritten in step 6.

## 7. Risks and mitigations

- **A native chart painter is the largest single piece.** Tick logic comes from
  `matplotlib.ticker`; series maths exist; the painter is lines, polygons, text. The
  contingency in §3.4 keeps the first release usable if it slips.
- **Two overlay painters avoided, one renderer extended.** `OverlayRenderer` already
  abstracts the mapping; adding a stroke scale is small, and the parity test compares a
  Viewer frame and a page item of the same look.
- **Vector export of raster images.** Images embed as raster at native resolution inside
  SVG / PDF; overlays, charts and text stay vector. The bundle states the embedded pixel
  size.
- **Memory.** Window reads, not whole planes; the 100 Mpx render ceiling; expensive sources
  gated by the governor's estimate; per-item render cache keyed by item digest.
- **Format churn.** One version bump with a loader, partial-merge, round-trip identity test.
- **Catalog gates.** No op changes; the roles-file edit is a page description; function
  names stay unique across `nodegraph/catalog/`.
- **Headless parity.** The offscreen subprocess renders the same scene; the conformance
  test compares digests.
