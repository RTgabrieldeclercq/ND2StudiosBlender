# V4.00 — beta tests: what to check by hand after each step

Companion to `V4.00_workspaces.md`. The gates prove the code; these checks prove the
**experience** — the things a probe cannot see (a window that feels wrong, a menu in the wrong
place, a black frame). **Each step's block covers only what that step added**; run it after the
step's PR is merged (or on its branch) and record Pass / Fail / Note per row. The regression
sweep at the end is a separate, optional pass for the moment a step is merged into `Blender`.

## How to run any beta pass

1. **Get the build.** `git switch Blender && git pull` (or the step's branch). Then:
   ```
   .venv\Scripts\python.exe -m pip install -r requirements.txt      # only when the step says so (step 7 adds matplotlib)
   ```
2. **Run the gates first.** If one is red, stop and report it; the beta checks assume a green build.
   ```
   set PYTHONUTF8=1
   .venv\Scripts\python.exe -B -m nodegraph.selftest                      → ALL NODEGRAPH SELF-TESTS PASSED
   .venv\Scripts\python.exe scripts\_nodelab_v2_phase5_probe.py out.png   → ALL PHASE-5 GUI PROBES PASSED
   .venv\Scripts\python.exe scripts\_catalog_snapshot.py                  → CATALOG IDENTICAL
   .venv\Scripts\python.exe scripts\_codemap.py                           → CODEMAP CURRENT
   ```
3. **Launch** with `python run.py` (the venv's python). Open the console with **Ctrl+`** — it
   shows every pull, `cached` hits and refusals, and is what to paste when something fails.
4. **Test data.** Two inputs cover everything:
   - the **synthetic demo**: click the welcome card's example graph (blank canvas → the card is
     centred; its button builds an 8-node demo), or add a Load card and leave its path empty —
     an empty path is the synthetic stack;
   - **one real ND2** with several stage positions (M ≥ 2) and several time points (T ≥ 5); note
     its name in the results, the position/time checks need it.
5. **Reporting a failure.** For each Fail give: the check id, what you clicked, what you saw,
   what you expected, the last ~10 console lines, and the saved file if the check involves one.
   Paste the results table into the chat with Claude or drop it in
   `CodeLog/Updates/beta/<date>_step<N>.md`. A failure becomes a worklog entry on a fix branch,
   never a fix on `Blender`.
