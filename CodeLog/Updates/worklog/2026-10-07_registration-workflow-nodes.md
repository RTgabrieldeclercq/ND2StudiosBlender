## What changed

The registration WORKFLOW becomes three small nodes instead of one node that knows everything. **Shift** (`align.shift`, category registration, `nodegraph/catalog/align/shift.py`) is the apply half of registration on its own: it takes the data to move on `data` and the shift **as a function of time** on a second input, `shifts` — the `drift_y` / `drift_x` (/ `drift_z`) Frame layers a Registration or Drift Correction output already carries (unwired, the data's own layers) — and moves every plane, channel and position of the data by its frame's (z, y, x) shift, lazily per plane (2D lever) or per volume (3D, with an optional `shift_z` layer; blank = no axial shift). A one-position shift source applies to every position; a timepoint mismatch, a missing layer and a Dataset carrying structure tables are refused with the real message; `invert` negates; masks and label rasters ride along at order 0; the applied shift is stored as `shift_y` / `shift_x` (/ `shift_z`) Frame layers so the demo window reads it back. It applies through the same `apply_shift` call Registration's `apply_frame` makes, so `Shift(data, Registration(data)) == Registration(data)` bit for bit, and the shift vector is folded into the streaming fingerprint by content (it comes from the second input, which the base provider's fingerprint cannot see). **Select Plane** (`util.select_plane`) keeps ONE z plane (auto = the middle plane, `derive="(n_z or 1) // 2"`; a new **`plane` instant pick** adopts the Z plane the Viewer shows), narrowing Z to 1 with `origin_um` at the plane's height, `z_step_um` kept, lattice layers and structure rows following through the shared frame-subset helpers, a z-only sampling stamp, refusal past the end with the depth, identity on a single-plane input; its edit-time twin `metadata.select_plane` / `plane_pick` keeps the card and the pull in agreement. **Split Z** (`util.split_z`) is the Z member of the tap family: a pass-through whose card grows `z0…zZ-1` sockets (labelled with the plane's height) that `ops.materialize_plane_taps` turns into one shared `util.select_plane` tap per plane at graph-build, between the position and channel taps. Registration itself is unchanged apart from pointers to the workflow in its 2D choice doc, description and docstring. Demos: Select Plane and Split Z on the nuclei stack; Shift with two scenarios that run the WHOLE chain (`data_from: src`, prelude Select Plane → Registration, `extra_inputs.shifts = pre 1`) — drifting beads, and the 12-plane bead stack registered on its middle plane — with the applied shift read back against the true drift. MANUAL §15 rows (Registration 4, Transform & utility 15), a §16 C recipe for the stack workflow, the §8b pick table, `registration.md` §11, the kernel README row, roles (plus `op_pages` so the two plane nodes are offered on the refine page beside Registration), the demo curation, three selftests and a GUI probe block.

## Why

The request, in three steps: a 2D mode for Registration where the user picks a z plane, the translation is estimated on that one plane and applied to every plane the same way — then, rather than baking that into one node, a **Shift node that takes a per-frame (x, y, z) shift and shifts all the data by it**, because a plane picker inside Registration couples the estimate to the apply and to the data the estimate ran on; then a **Split Z** node so the plane can be chosen on the canvas. So the decoupled workflow is `stack → Select Plane (or a Split Z tap) → Registration (2D) → Shift(stack, shifts = Registration's output)`: each node stays small, and each half can be swapped (estimate on a z-projection or one channel instead; apply a shift that came from somewhere else). The shift source is the Frame layers Registration already writes — a second Dataset input with `layer_from="shifts"` — because that is the engine's existing way of carrying one value per (position, frame) along a wire; a numeric socket could never be a function of time. Split Z mirrors Split Positions / Split Channels exactly (synthetic sockets from the envelope, a shared tap per index, the tap carrying the INDEX because a plane has no name) so it behaves like the family users already know, and the `plane` pick mirrors `frame` / `channel` (instant, nothing to aim: the answer is on screen). The middle-plane default is what Registration's 2D path always estimated on, now visible and overridable. Shift refuses structure tables as Transform does, for the same reason (a moved raster with unmoved rows reports every object where it used to be); masks move so a segmentation upstream is not silently misaligned. The `shift_y`/`shift_x` sockets go through the shared `_resolve_layer` because the socket contract requires every REQUIRED layer socket to — the gate caught the bare `ctx.layer` read on the first run.
