## What changed

V4.00 step 5 of `CodeLog/ClaudesPlan/V4.00_workspaces.md`: **the pages of a workspace are on
screen.** Until now the window showed the workspace's active page alone; now every page has
its own canvas scene and the user moves between them.

- **Canvases and the page switcher.** `nodelab_v2/canvas.py` `CanvasPanel` is a canvas bound
  to one page: a `GraphView` on the page's scene, its own welcome card and mini-map, and the
  **page switcher** — `GraphView.page_button` in the top-left corner, naming the page with its
  kind's coloured dot. Its menu lists every page grouped by kind (the shown one ticked) and
  adds a page of any kind, duplicates, renames, deletes (confirmed when it has nodes; greyed
  out for the last page) or opens it in a new canvas. Ctrl+PgDn / Ctrl+PgUp step through the
  pages. A canvas remembers where it was looking at each page.
- **One scene per page** (`MainWindow.scene_for`), made the first time a canvas shows the page
  and kept until it is deleted, so a page keeps its selection, run states and layout while no
  canvas shows it. Its signals and its document's listeners are wired once (`_wire_scene`) and
  removed with it.
- **Several canvases.** The MAIN canvas is the window's central widget; every further canvas
  is a `canvas:<n>` dock (View ▸ New ▸ Canvas, or "Open in a new canvas") that pops out, tabs,
  closes and comes back with the layout (`binding_of` = its page). The canvas pressed last
  (a press or a drop activates it before anything else happens — `GraphView.pressed`) is the
  ACTIVE canvas and its page the workspace's active page; `MainWindow.doc`, `scene`, `view`,
  `minimap` and `welcome` are now properties of the active page and canvas, so every edit lands
  on the page on screen. The palette, the inspector (the page's own selection), the window
  title (`… — Image Refinement · dish A`) and an accent on the switcher (with several canvases)
  follow it.
- **Nodes by page kind.** `scene.visible_specs(kind)` / `compatible_ops(..., kind)` and
  `readiness.producers_of(domain, kind)` offer the ops `nodegraph.roles` assigns to the kind;
  the palette's chip says which (`PalettePanel.set_page_kind`). A later page with no source is
  suggested a Page Input, not a Load. The link-drag search opens on the view the drag ended in.
- **Page boundaries in the inspector and on the cards.** A Page Input's `source` is a closed
  dropdown of the named Outputs the page may read (`Input page · raw`), keeping an unbound
  value visible rather than rewriting it; the cards read `Output · raw` and `Input · raw`.
- **Runs on every page.** The run handlers route card states to the run's own page's scene
  (a run that crosses pages claims the cards of each page it computes on, keyed by its run id
  there), and viewers key results by the page-qualified run id (`pg1/n3`) while showing the
  node's own id (`viewer._short`), so two pages' `n3` never share a picture or a contrast
  setting. `pull_node(page_id=)`, the iteration strip, overlay pins, play gates and the
  Viewer node's settings work on the node's own page.
- **The two items deferred from step 2.** (1) A dock fed through a Page Input folds the
  upstream pages' chains into its signature (`Workspace.cross_page_signature`, a document
  hook), so an edit on an upstream page stales it — while a dock whose chain stays on its page
  keeps exactly the signature its bake recorded; `dock_status` takes the signature and keys
  its memo on the workspace's run identity of the page. (2) `EngineRunner.invalidate` drops
  held views and cached planes only on the pages the edit can reach (the touched pages and
  every page that reads them, `_pages_reading`; `PlaneCache.drop_where`), so another page's
  viewers keep scrubbing from memory; an unknown edit still clears everything.

**Deviation from the plan.** "No central widget" proved unworkable: without one, Qt gives the
side columns every spare pixel and squeezes a top/bottom dock to its minimum width (measured
offscreen; Qt documents a main window without a central widget as unsupported). The main
canvas is therefore the central widget — it cannot float or close, which also makes "the last
canvas cannot be closed" automatic — and every further canvas is a dock. Recorded in the plan.

**Found while testing, fixed here.** Opening a file of several pages over a window whose
active page had another id showed the wrong graph: the workspace load keeps the active page's
document object for the NEW active page, so the scene cached under the old id now showed the
new page's nodes. `_sync_pages` drops every scene whose page is gone or whose document changed
and re-points the canvases that showed it (probe PG8; reproduced first).

**Review (an adversarial pass: three lenses, every finding reproduced, then verified by a
second agent).** Eight confirmed, all fixed here with a regression check:

- *A pick applied after another canvas was clicked wrote into the active page's node of the
  same id* (a duplicated page holds the same ids). The viewer now remembers the page a pick
  was armed for (`ViewerPanel.arm_pick(page_id=)`, `pick_page_id`), and the commit, the draw
  controls and the region round trip (`_pick_return` is `(page, node)`) act on that page.
- *The Movie Editor resolved its bare node id on the active page*: a fetch for its page was
  dropped while another page was shown, and its edits landed in another page's same-id
  Export Movie. It is bound to the page it was opened on (`_movie_pid`); every host call and
  the Export Movie helpers take that page, its title names it, and a save stamps every page's
  movies.
- *A Hold or a Bake left its run's claim on the other pages' canvases* (only finished,
  failed and cancelled runs retired it), so later runs left cards reading `queued`.
  `_retire_claims` now ends every kind of run.
- *Shift+F5, F9 and the re-pull after Hold/Bake/Release did nothing* when the active Viewer
  showed another page's node (`_viewed` names an active-page node only): `_repull_viewed`
  pulls the Viewer's binding on its own page.
- *File ▸ Open left a dropped scene listening to a live document*: the next edit raised
  before the live canvas updated. `GraphScene.release()` unhooks it.
- *An edit on another page dropped this page's overlay context* while keeping its held view,
  so the overlay vanished on the next scrub; it also cancelled this page's preload. Overlay
  contexts, the per-source LUT cache and the preload now follow the edit's reach.
- *Renaming a page did not stale a dock under a blank-condition Page Output on that page*
  (compose stamps the page name there). The signature hook folds that name in.
- *Properties went stale when a page was renamed or deleted from another canvas's switcher*
  (the active page did not change, so nothing rebuilt it). The panel is rebuilt whenever the
  page list changes.

Refuted on verification: a node dragged from the palette onto another canvas lands on that
page even when its kind does not offer it. Page kinds filter what the menus offer, as the
roles file and the MANUAL say; the Example graph and file loads place off-kind nodes the same
way. The MANUAL now says so explicitly.

**Not in this step.** Publishing a LabLink recipe still sends the active page's document alone,
so a page that reads another through a Page Input cannot be published as a runnable recipe
yet (the worker already runs workspace files by page).

Tests: selftest `test_pages_seam` (readiness by kind and the Page Input suggestion; the
cross-page dock signature — stale on an upstream edit and on a rename under a blank-condition
Output, unchanged for a single-page dock; the pages an edit reaches and

its palette/link search/title, a Page Output read through the Source menu and pulled, two

## Why

V4's point is several typed pages — Input, Refinement, Processing, Analysis — each its own
graph, handing named outputs to the next. Step 1 built the model and step 2 the runner on it;
until this step the user could not see or reach any page but one. Per-page scenes rather than
re-filling one scene: a page keeps its state (selection, card run states, positions) while it
is off screen, and two canvases can show one page. Page-qualified viewer ids rather than bare
ones because every page numbers its nodes from `n1`: with several pages, bare ids collide on
the first click.

## How to verify

`python run.py` → Example graph → the switcher (top-left) → New page ▸ Image Refinement: the
palette shrinks to refinement nodes → back on the first page add a Page Output named `raw`
after Select Channel → on the Refinement page add a Page Input, pick `Graph · raw` from its
Source, add a Gaussian after it and double-click it → View ▸ New ▸ Canvas and switch it to the
first page; click in each canvas. The beta block B5.1–B5.15 lists the rest.
