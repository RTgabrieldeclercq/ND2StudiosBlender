  whose Page Inputs were unbound on the worker.

## Why

Step 10 of the plan: the documentation sweep that closes V4.00. Writing §2b's last step
("publish the Analysis page as a recipe") exposed that the workspace draft promised in step 1
(`draft_from_workspace`, the manifest `page`) was never built — the worker could run a page of
a workspace, but nothing could publish one. Documenting the gap instead would have shipped a
walkthrough whose last step fails. The review then found that a LabLink hub installs single
graphs only, so the page is published flattened — which needs nothing new on the worker or
the hub.

## Review

An adversarial review (two lenses: the publish feature, the documentation against the code;
every finding verified independently) confirmed 11 findings. All are fixed:

- **Every Publish crashed** (`NameError`): the recipe dialog read a `graph` it was never given —
  single-graph publishes included. Nothing constructed the dialog in any test; probe PB1 now
  builds it for a single graph and for a flattened page.
- **The hub refused the recipe.** The first design published the WHOLE workspace (format 3.0)
  with a manifest `"page"`, but a LabLink hub (the sibling `lablink` repository) installs format
  2.0 only and never forwards `page`. The page is now published flattened into one 2.0 graph;
  the hub's own `load_recipe` accepts it (checked against the hub code on this machine).
- **A lever inside a group was not pinned** in the workspace document (the composed id
  `pg3/M%grp5` matched no page node). The flattened graph has the group expanded, so the
  ordinary pinning reaches it.
- **A plot-only page targeted Export Figure**, so the default run returned an empty table; it
  now targets what feeds the first plot.
- **Docs:** §18's nine new rows sat after a blank line, outside the table; §2b step 5 left Table
  Aggregate's Table blank (Table Concat passes input 0's own table on too, so it refused); one
  quoted error text was not the real one; CON-18 / WF-08 overstated what a linked page shares
  (a root on the linked page is its own); WF-08 / INV-15 put run-id qualification in the wrong
  place (the window qualifies; `run_id` and `compose` read a bare id); INV-16 said the catalog
  gates never see the page ops (the snapshot and the synopsis do).
