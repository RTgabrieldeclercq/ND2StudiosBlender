## What changed

A new utility node, **Trim** (`util.trim`), scales one axis down to evenly spaced frames.
Trimming 12 timepoints to a third keeps frames 0, 3, 7 and 11. **Axis** picks T (the
default), Z or M. **Size by** takes either a `fraction` of the axis (default 0.5) or a fixed
`count` of frames. **Spacing** picks the frames in one of two ways:

- `span` covers the first frame to the last, using `i·(n−1)//(k−1)` in integer maths, so
  there are no float edge cases.
- `stride` takes one uniform step from frame 0 (12 → 4 keeps 0, 3, 6, 9).

`span`'s steps are uneven unless (n−1)/(k−1) is a whole number, so it drops `dt_s` /
`z_step_um` rather than averaging them. `stride` keeps them, multiplied by the step. Either
way, the per-frame clock still gives every kept frame its true time.

It is a lazy `FrameSubsetProvider` view, TILEABLE, with no 2D/3D lever. It reuses Crop's
frames-mode machinery: `subset_lattice_layers` / `subset_structure_rows` and the per-axis
metadata helpers (`time_subset`, `position_subset`, `respaced`, `z_home_after`,
`scope_stamp_subset`). So masks follow the kept frames, detections and tracks on dropped
frames are removed, and per-frame lists stay in step. A local `meta_transform` shares its
pick and metadata logic with the compute (`trim_picks` / `trim_changes`), so the card's
predicted axes match the pull.

Hotspot files touched:

- `nodegraph/catalog/__init__.py`: `util.trim` appended to `MODULES`.
- `nodegraph/selftest.py`: `test_trim` after `test_time_shift`, plus its `main()` line.
- `codemap/gen/*`, `codemap/node_synopsis.json`, `scripts/catalog_baseline.json`:

Also added: a `node_roles.json` entry (dataset & channel organization), a `node_demos.json`
entry (star_field, fraction 0.5), and a MANUAL §15 row.

## Why

The request was a node that thins an axis, for example a 12-frame T to a third giving frames
0, 3, 7, 11, and that works before or after a Timeseries Builder. Crop's frames mode already
does the subset, but it needs a typed index list. That list does not scale from a 12-frame
test file to a 1,200-frame run, and it has to be retyped whenever the series length changes.

Trim keeps Crop's subset code and only adds the rule that picks the indices. A second copy of
the structure-renumbering and per-T-list rules would be the kind of thing that gets fixed in
one place and not the other.

The before-builder case works because `time_subset` already re-indexes a multi-file card's
per-file clocks (`source_frame_time_jd`) one level down. The builder therefore still
interleaves the surviving frames by real acquisition time. The test checks this for one
bundle card and for separately trimmed cards.

Before and after the builder give different frames when files interleave. Before the builder,
each file is trimmed on its own. After it, the series is trimmed in acquisition order. The
MANUAL row and the Axis docs say so.

`stride` exists because `span` matches the requested 0, 3, 7, 11, but its uneven steps cannot
carry one `dt_s`. Users who need calibrated speeds downstream need an exactly uniform option.

A fraction above 1 is refused rather than clamped. A "3" typed into Fraction most likely
meant "a third", and silently handing back every frame would hide that.

## How to verify

- `PYTHONUTF8=1 .venv\Scripts\python.exe -B -c "import nodegraph.selftest as S; S.test_trim()"`
- In the app: Load an ND2 time series → Trim (Fraction 0.33) → Viewer. T shows a third of
  the frames, and the timestamp overlay reads each kept frame's real time.
- Or: two loaders → Trim each → Timeseries Builder. The built series interleaves the kept
  frames by clock.
